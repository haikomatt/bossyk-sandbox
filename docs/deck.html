bossyk -- agent governance

Govern the effect an action would have. Attest the record. Do not try to read intent.

Act 1

The threat surface

What are we trying to detect?

  • live measurementWe attacked the same guardrail the same way across two very different businesses to see if the weak spots were a fluke.
  • live measurementThe attacks aren't scored on how sneaky they sound -- they're scored on whether the agent would actually do something dangerous.
Act 2

Layered defence

At what level do we detect it?

  • live measurementThe input filter lets through roughly one in five attacks on a real booking system, and about one in six on a real shopping one.
  • live measurementThe filter is excellent at spotting messages that sound like attacks, and almost blind to requests that just sound like normal customer support.
  • scripted proxyBecause the front-door filter can't judge intent, a second layer watches what the agent actually does, not what it was told.
  • live measurementWhen an agent is misconfigured to skip its own checks, the same attacks a careful agent shrugged off now go through -- and the governance gate stops every one before it executes.
Act 3

The method

How do we test it?

  • scripted proxyNo single detector catches every bad action, but the three together caught all of them in our test set.
  • modeled counterfactualTo test whether catching a problem actually stops it, we replay real detection decisions against the moment right before the action ran.
Act 4

Why not just read the model?

Can reading the model's internals catch a violation on its own?

  • live measurementReading the model's internal state can tell that a violation is coming, but only because the request already says so in words. It adds nothing a plain text classifier does not already see.
  • live measurementThe model does not privately think about the violation before doing it. An instruct model acts on the very first token, and a reasoning model reasons its way to compliance, so there is no hidden window to read.
  • live measurementAnd you cannot hide the intent from a plain text monitor in this domain. A request that still makes the change cannot be laundered clean, so there is no gap for the internals to win in.
  • live measurementSo the demonstrator does not try to read intent. It governs the effect the action would have and signs an independent record of it, which is the thing an adversary cannot cheaply fake.
Act 5

The evidence

What backs each claim?

  • modeled counterfactualYou can see far more problems than you can actually stop before they happen.
  • live measurementWe now measure exactly how much faster detection would have to be to stop a problem instead of only noticing it.
  • deterministic recomputeEvery claim in this story says out loud how solid the number behind it actually is.
  • deterministic recomputeEvery deterministic number in this repo can be regenerated from scratch and comes out byte-for-byte identical.
  • deterministic recomputeEvery governed action is written to a signed, tamper-evident log -- the same record a regulator or auditor would ask to see, produced automatically.
Act 6

Honest limitations

What do we NOT know yet?

  • openWe still don't know if the agent-layer watchdogs actually catch the attacks that got past the front door.
  • live measurementA safety-trained model refused to be our attacker at all -- every single time.
  • openThe H1 numbers describe the filter in isolation -- they don't yet describe what an agent would have done with those attacks.
  • deterministic recomputeWhen a judge fails to answer, we record that it failed -- we don't quietly treat silence as 'all clear'.
Act 7

The loop

How do we remediate and learn?

  • deterministic recomputeA failure we only caught after the fact became a rule that stops it before it happens.
  • deterministic recomputeA caught failure becomes a permanent, replayable rule -- not a one-off alert that gets forgotten.
  • openWe haven't yet tested against an attacker specifically trying to slip past every layer at once.
  • scripted proxyA caught action does not just get a yes or no. It gets a graded response, so the safe path keeps moving and only the genuinely hard cases stop.
  • scripted proxyThe only actions a person reviews are the genuinely hard ones, and they are handled by callback, so nobody is left waiting on hold.
  • deterministic recomputeActions inside a session's delegated authority are accepted and approved in the background. Only the over-limit ones reach a person.
